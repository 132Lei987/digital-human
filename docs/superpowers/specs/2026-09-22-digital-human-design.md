# 文旅数字人「真人对话」功能设计

> 工单编号：人工智能CV-AIGC-18-文旅智能体-智能导览与互动体验任务
> 日期：2026-09-22
> 状态：已确认（待实现）

## 一、目标

构建一个「能像真人一样对话的数字人」网页应用：

- 游客用**文字输入**提问；
- 后端调用 **DeepSeek-flash** 大模型生成回复；
- 用 **Edge TTS** 把回复合成语音，并拿到**字级时间戳**；
- 前端播放语音的同时，按时间戳切换数字人的**嘴型帧**，实现「嘴跟话走」的口型同步效果。

首版聚焦「文字 → 语音 + 口型同步」这条核心链路，语音输入（ASR）留待后续迭代。

## 二、范围界定（YAGNI）

**本版本做：**
- 文字输入 → DeepSeek-flash → Edge TTS → 语音 + 口型同步
- 2D 数字人形象（从素材视频抽帧 + 4 张嘴型帧切换）
- 网页前端（原生 HTML/JS）+ 后端（FastAPI）

**本版本不做（后续迭代）：**
- 语音输入（ASR）、实时打断、多轮上下文记忆（每次独立问答）
- 3D 数字人、Live2D 模型
- 多端（App/小程序/自助终端）、用户登录、持久化存储

## 三、整体架构与数据流

```
你打字 "介绍一下这个古城"
   │  POST /api/chat  {message}
   ▼
后端 FastAPI
   │  ① 调 DeepSeek-flash → 回复文本
   │  ② 调 Edge TTS → 生成音频 + 字级时间戳 words[]
   ▼
返回 JSON：{ reply_text, audio(base64), words:[{text, start_ms, duration_ms}, ...] }
   │
   ▼
前端浏览器
   播放 audio，同时用 requestAnimationFrame 循环对比当前播放时间
   命中某个字 → 切换到对应嘴型帧（闭/微张/半张/全张）
```

**关键点：** 音频 + 每个字的起止时间由后端一次性返回，前端只负责「对表切帧」，无需自己分析音频。

## 六、核心算法细节

### 6.1 抽帧生成嘴型（离线，跑一次）

从 12 秒视频中挑出嘴巴处于 4 种不同开合状态的帧。判断嘴巴开合：检测嘴巴区域像素变化（张嘴时口腔/牙齿颜色与闭嘴不同）或嘴巴区域面积。

抽到 4 帧后，**除嘴巴那一小块以外的画面锁定为同一张底图**，避免抽帧时背景/头发微动导致画面抖动；前端切换时只换嘴巴区域。实现时需记录**嘴巴区域在画面中的坐标（bounding box）**，前端据此用 CSS 定位叠加或 Canvas 合成来替换嘴巴局部。

**边界情况：** 若视频中数字人始终处于说话状态、抽不到清晰的「闭嘴」帧，则用 AI 局部重绘（inpainting）补一张闭嘴帧，或从最接近闭嘴的帧中选用；其余三档同理按开合程度就近归类。

### 6.2 字级时间戳 → 嘴型映射

Edge TTS 的 `WordBoundary` 返回每个字的 `start_ms` 和 `duration_ms`。前端两层映射：

1. **说话中 vs 停顿**：当前时间落在某字 `[start, start+duration]` 内 → 说话，否则闭嘴（mouth_0）。
2. **张嘴幅度**：按字的 `duration_ms` 长短映射——发音时间越长嘴张越大（长音=全张，短音=半张/微张），叠加随字切换的微小抖动使其更自然。

### 6.3 播放与切帧同步

- 音频用 HTML5 `<audio>` 播放，切帧用 `requestAnimationFrame`（每帧约 16ms 检查一次当前播放时间），嘴型与音频毫秒级对齐。
- 一次回复播完，数字人回到闭嘴待机帧。

## 七、错误处理与边界情况

**后端：**
- DeepSeek 调用失败（网络/超时/Key 无效）→ 返回带 `error` 字段的友好提示，前端播兜底语音，不卡死。
- TTS 合成失败 → 返回兜底回复，不影响已生成的文本。
- API Key 未配置 → 启动时校验，缺失则控制台提示并拒绝 `/api/chat`。

**前端：**
- 播放被中断（连续发多条）→ 新回复到来时停止上一次音频和切帧循环，只播最新一条。
- 音频加载/解码失败 → 显示文字兜底，界面不无响应。
- 时间戳为空 → 退化为「响度驱动」或「固定节奏」后备，保证嘴仍会动。

**配置与安全：**
- DeepSeek API Key 放 `.env`（环境变量），不硬编码、不提交 git。

**资源缺失：**
- `assets/mouth_frames/` 缺失时，前端显示占位图并提示先运行 `mouthframes.py`。
